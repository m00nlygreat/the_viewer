# .diff/.patch·.env 지원 계획

- 작성일: 2026-11-07
- 상태: 구현 전 계획. 현재 작업 트리의 소스를 기준으로 하며, 제품 코드 변경은 포함하지 않는다.
- 구현 기준: 파일별 작업·타입 계약·검증·실행 순서는 새 [구현 지시서](DIFF_ENV_IMPLEMENTATION.md)를 따른다. 이 문서는 범위와 설계 배경을 보관한다.
- 기준: [요구사항](../wiki/REQUIREMENT.md), [용어](../wiki/TERMS.md), [컴포넌트 작성 규칙](COMPONENTS.md).

## 1. 범위와 기본안

사용자가 지정한 범위는 다음과 같다.

- `.diff`와 `.patch`를 같은 형식으로 취급하고 저장된 diff 내용을 고정폭 글꼴로 렌더링한다.
- `.env`는 JSON/YAML/TOML 캔버스 편집기를 재사용하며, 팔레트에는 프로퍼티와 값 두 종류를 둔다.
- 공통 레이아웃·모듈을 정의하고 컴포넌트 단위로 재사용한다. 기존 `보기 / 원본`, 저장·다운로드, 공통 이력·복구 규칙을 따른다.

세부 구현의 기본안은 다음과 같다. 기존 형식의 요구사항·GUI 표시명은 유지한다.

| 대상 | 기본안 |
| --- | --- |
| `.diff`, `.patch` | 내부 형식 하나인 `diff`에 두 확장자를 연결. 나란히 보기를 기본으로 제공하고 한 열 unified 보기와 기존 원본 편집기로 전환 가능 |
| diff 보기 | 파일별 구분, hunk 헤더, 이전/이후 행 번호, 추가·삭제·문맥 표시. `한 줄로 보기`와 `나란히 보기`를 제공하고 긴 줄은 보기 너비에 맞춰 줄바꿈 |
| `.env` 파일명 | `.env`, `*.env` 인식. `.env.local`·`.env.production` 등 `.env.*`도 파일명 규칙으로 같은 형식에 연결하는 안 |
| `.env` 값 | 모두 문자열. 숫자·불리언·null·객체·배열로 자동 변환하지 않음 |
| `.env` 캔버스 | 평면 프로퍼티 목록과 문자열 값 칩. 컨테이너·스키마 팔레트는 제외 |
| `.env` 출력 | `.env` 미리보기·복사·동일 형식 파일 출력. JSON/YAML/TOML 상호 변환 목록과는 별도로 구성 |

## 3. 공통 레이아웃과 컴포넌트

공통 UI는 `src/features/block-editor/`에 추출한다. 기존 `StructuredDataEditor`는 JSON/YAML/TOML 어댑터로 유지하고, `.env`는 별도 `EnvEditor` 어댑터를 둔다. 아래 새 파일명은 구현 모듈 제안이다.

```text
StructuredDataEditor ─┐
                     ├─ BlockEditorLayout
EnvEditor ───────────┘    ├─ BlockPalette
                         ├─ BlockCanvas
                         │   └─ 공통 프로퍼티 행·값 칩 + 형식별 루트 렌더러
                         └─ BlockOutputPanel

DiffView ─────────────── 별도 문서 렌더러
```

| 컴포넌트·모듈 | 책임과 재사용 경계 |
| --- | --- |
| `BlockEditorLayout.tsx` | 왼쪽 팔레트·중앙 캔버스·오른쪽 출력 슬롯 배치, 패널 폭·접힘과 반응형. 문서 형식·파서에 의존하지 않음 |
| `BlockCanvas.tsx` | 격자·좌표 변환·루트/미연결 블록 배치·확대 도구·드래그 고스트. 루트와 노드 렌더러를 주입받음 |
| `BlockPalette.tsx` | 항목 정의와 payload 생성 함수를 받아 포인터·키보드 추가 UI 제공. 스키마 같은 형식별 영역은 슬롯으로 받음 |
| `BlockPropertyRow.tsx`, `BlockValueChip.tsx` | 기존 회색 프로퍼티 행, 빈 소켓, 값 칩, 인라인 편집, 긴 값 펼침을 공유. 중첩 노드·날짜·색 보조 UI는 어댑터에서 연결 |
| `BlockOutputPanel.tsx` | 출력 결과·점검 결과·코드 렌더러·복사 콜백·선택 가능한 형식 목록을 props로 받음. JSON/YAML/TOML 목록을 내부에 고정하지 않음 |
| `useBlockEditor.ts`, 공통 `BlockContext` | 선택·편집·접힘·드래그 상태와 불변 변경 요청 관리. 실제 변경은 `onChange`로 전달 |
| `useCanvasViewport.ts` | 팬·휠/핀치 확대·맞춤·좌표 계산과 이벤트 해제. 문서 모델·직렬화와 독립 |
| 블록 정책 모듈 | 허용 노드·값 타입, payload 생성, 드롭 허용, 변경 검증, 값 표시 방식 정의. UI 노출과 실제 명령 양쪽에서 사용 |

공통 경계는 다음 계약을 따른다.

- 모델은 기존 `StructuredModel` 그래프를 사용한다. 공통 UI는 문서 파일 핸들·Chrome API·파싱·직렬화를 직접 호출하지 않는다.
- 어댑터가 `model`, `readonly`, `policy`, `onChange`, 렌더러와 출력 결과를 제공한다. 레이아웃은 React 슬롯을 받아 배치한다.
- JSON/YAML/TOML은 기존 컨테이너·프로퍼티·값·스키마·출력 탭·표시 힌트를 그대로 연결한다.
- `.env`는 프로퍼티·문자열 값 항목만 제공한다. 루트는 고정된 평면 객체이며 삭제·분리하지 않는다. `EnvRootBlock`에서 공통 프로퍼티 행을 사용한다.
- `.env` 정책은 타입 변경과 날짜·색 추론을 끄고, 중첩 컨테이너 드롭을 거부한다. 값의 분리·재연결, 미연결 블록, 키보드 조작은 기존 캔버스 동작을 재사용한다.
- 캔버스·선택 상태는 편집기 인스턴스에 한 번만 둔다. 문서 전환 때 상태가 섞이지 않게 하고, 재파싱으로 사라진 선택·편집 대상을 정리한다.
- 접힌 출력 패널은 미리보기·점검을 계산하지 않는다. 복사를 요청할 때 현재 모델에서 출력한다. 스키마 추론도 해당 팔레트를 사용하는 어댑터에서만 실행한다.

공통화는 레이아웃부터 작은 단계로 진행한다. 기존 그래프 연산을 재사용하고, 네 형식을 위한 범용 플러그인 체계를 추가하지 않는다.

## 4. .env 모델·파싱·원문 보존

`StructuredFormat`은 JSON/YAML/TOML 출력 형식으로 유지한다. `.env`의 재사용 여부는 별도 블록 편집기 판별과 정책으로 표현한다.

- 새 `EnvModel`은 공통 그래프인 `blocks: StructuredModel`과 `.env` 구문 메타데이터를 가진다. 루트 항목은 순서 있는 `StructuredSlot`이고 값은 문자열 scalar다.
- 주석·빈 줄·키/값 범위·인용 방식·`export` 접두어·행내 주석·개행 정보를 별도 구문 모델에 보관한다. 항목은 키 문자열 대신 슬롯 ID로 연결하여 중복 키도 보존한다.
- `.env` 파싱·검증·원문 패치·출력은 `src/domain/env/`에 둔다. 파싱은 기존 파서 Worker로 실행한다. 공통 UI가 `.env` 구문을 해석하지 않는다.
- `.env`에는 단일한 공식 규격이 없으므로 [Node.js DotEnv 명세](https://nodejs.org/api/environment_variables.html#dotenv)를 문법 기준으로 삼는 안을 사용한다. `KEY=VALUE`, 빈 값, 작은/큰따옴표, 인용된 여러 줄, 주석과 `export`를 다룬다. 변수명은 해당 명세의 문자·숫자·밑줄 규칙으로 검증한다.
- `0`, `true`, `null`, JSON처럼 보이는 문자열도 문자열로 유지한다. 변수 치환·셸 실행은 하지 않으며 `${NAME}` 같은 내용은 텍스트로 보존한다. 이스케이프·인용 경계는 선택한 명세의 실제 파싱 동작과 fixture로 고정한다.
- 단순 객체를 반환하는 파서 결과만 사용하지 않는다. 중복 키는 합치지 않고 각 행을 유지하며, 점검에서는 중복 위치를 안내한다.
- 키 또는 값 편집은 해당 토큰만 교체한다. 필요할 때 인용을 보완하되 미편집 공백·주석·개행은 유지한다. 원문 범위는 fingerprint와 revision으로 검증한다.
- 추가·삭제·재정렬은 구문 항목 단위로 처리한다. 기본안은 선언과 행내 주석을 함께 이동하고, 독립 주석·빈 줄은 기존 위치에 보존한다. 선언 삭제로 독립 주석까지 삭제하지 않는다.
- 편집 결과는 다시 파싱하여 같은 키·값·순서를 얻는지 확인하고 범위를 갱신한다. 표현할 수 없는 변경은 원문을 덮지 않고 초안으로 유지한다.
- 값이 없는 소켓은 미완성 초안이고, 빈 문자열은 유효한 `.env` 값이다. 잘못된 키·미완성 값은 출력하지 않으며, 로컬 초안 복구와 공통 Undo/Redo에는 포함한다.
- 원문 문법 오류에서는 입력 원문을 보존하고 마지막 유효 캔버스를 잠근다. 원본 편집·회수는 기존 세션 정책을 따른다.

## 5. .diff/.patch 렌더링

- [형식 등록](../src/domain/fileFormats.ts)에 `diff` 하나를 추가하고 확장자 별칭을 `diff`, `patch`로 지정한다. 파일명·저장 확장자는 열었던 이름을 유지한다.
- `src/domain/diff/parse.ts`에서 원문을 파일·hunk·행 종류·이전/이후 행 번호·원문 범위로 분석한다. [Git diff 문서](https://git-scm.com/docs/diff-format#_generating_patch_text_with_p)를 기준으로 Git 확장 헤더도 구분한다.
- 읽기 전용 [DiffView](../src/features/diff/DiffView.tsx)에서 통합 한 열 보기와 이전/이후 나란히 보기를 전환한다. 보기 방식 버튼은 JSON/ENV 블록 편집기와 같은 우측 플로팅 버튼 셋으로 둔다.
- 본문·헤더·행 번호에 기존 `--font-mono`를 사용하고 탭·공백을 보존한다. 긴 줄은 diff 보기 안에서 자동 줄바꿈하고 상위 앱의 폭을 늘리지 않는다.
- 추가·삭제 배경과 `+`/`-` 표식을 함께 사용한다. 파일 헤더의 `---`/`+++`와 hunk 안의 삭제·추가 행은 파서 상태로 구분한다.
- 일반 unified diff와 여러 파일·hunk, 생성/삭제, 이름 변경·모드 헤더, 마지막 개행 없음 표식을 처리한다. 메일 형태 patch의 앞뒤 설명·통계도 버리지 않고 표시한다.
- binary patch·combined/context/normal diff·해석되지 않는 구간은 원문을 그대로 고정폭으로 표시한다. 일부 구간의 해석 실패로 파일 전체를 숨기거나 저장을 막지 않는다.
- diff 보기는 읽기용 렌더러로 두고 편집은 기존 원본 탭에서 수행한다. diff 자체를 비교 대상 파일에 적용하는 기능은 이번 범위에 포함하지 않는다.
- 직렬화는 분석 모델을 재조립하지 않고 현재 원문을 사용한다. 변경 없는 출력은 기존 바이트 기준을 보존하고, 원본 편집 뒤에는 최신 revision만 렌더링한다.
- 파싱은 행 수에 비례하도록 하고 행 내용은 가능한 한 원문 범위를 참조한다. 큰 파일의 DOM 비용을 측정해 필요한 구간만 가상화한다. 내용은 React 텍스트로 렌더링한다.

## 6. 앱·저장·중계 연결

| 경계 | 작업 |
| --- | --- |
| 형식·파일명 인식 | `FORMATS`, MIME, 확장자 별칭과 `.env.*` 파일명 규칙을 한곳에서 정의. 기존 MIME 우선순위는 유지하고 마지막 확장자와 형식 ID가 같다는 가정을 제거 |
| 일반 텍스트 MIME | `.env` 출력에는 `text/plain`을 사용할 수 있으나 형식 인식 별칭에는 등록하지 않음. 모든 일반 텍스트가 ENV로 열리는 문제 방지 |
| 타입·파싱 | `DocumentModelByFormat`에 `diff`, `env` 추가. [파싱 진입점](../src/domain/formatParsing.ts)의 마지막 VCF 대체 분기를 명시적으로 바꾸고 새 형식을 연결. diff 해석 경고와 env 문법 오류를 구분 |
| 편집·이력 | [문서 모델 경계](../src/domain/documentModel.ts), [컨트롤러](../src/domain/documentController.ts), [세션](../src/domain/session.ts)에 EnvModel 검증·초안 직렬화 연결. 문서/revision 확인·오래된 응답 폐기·저장 전 flush 유지 |
| 블록 초안 | 그래프 조회·미연결 블록 보존·dirty 판정·복구 가능 여부를 공통 헬퍼로 연결. `isStructuredFormat`에 env만 더해 기존 출력 변환 경로로 진입시키지 않음 |
| 보기·원본 | [App](../src/app/App.tsx)에 두 렌더러를 지연 로딩. env는 자체 캔버스 확대를 사용하므로 공통 `ViewerZoom`을 중복 적용하지 않음. diff는 기존 읽기 영역 확대 사용 |
| 파일 입출력 | 파일 선택·드롭·폴더·첨부·붙여넣기·새 문서·저장·공유에서 같은 형식 정의 사용. `.patch` 전용 형식/중복 새 문서 명령을 만들지 않음 |
| PWA·확장 | [Vite manifest 생성](../vite.config.ts), [자동 열기 규칙](../src/platform/extension/autoOpen.ts), [확장 URL 처리](../src/platform/extension/links.ts), [PWA 중계 검증](../src/platform/pwa/extensionRelay.ts)에 별칭·모델 연결. 파서·렌더러는 PWA에만 포함 |
| 변형 파일명 | `.env.*`는 basename 규칙으로 처리. `.local`·`.production`을 전역 지원 확장자로 등록하지 않음. OS 파일 연결처럼 확장자만 허용하는 경로에는 정확한 확장자만 선언하고 일반 파일 열기 경로 유지 |
| 복구 저장 | [저장소](../src/platform/storage.ts)에 빈 모델·깊은 모델/구문 범위 검증 추가. 기존 문서를 유지하고, 손상된 새 형식 레코드도 문서 단위 격리·재시도·백업 적용 |
| 문서·배포 | 구현 완료 때 [README](../README.md)와 위키의 지원 현황 갱신. 신규 의존성은 기본적으로 추가하지 않고 필요한 경우에만 검토 |

새 모델 추가만으로 IndexedDB 버전을 올리지는 않는다. 저장 구조 변경이 필요하면 기존 세션을 보존하는 이행 계획과 테스트를 먼저 마련한다.

## 7. 구현 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 공통 레이아웃·뷰포트·팔레트·행/값·출력 추출 | JSON/YAML/TOML의 기존 배치·드래그·키보드·출력·초안 동작이 유지됨 |
| 2 | diff 파서·렌더러·별칭 연결 | 같은 내용의 `.diff`와 `.patch`가 동일하게 열리고, 원문 손실 없이 편집·저장·복구됨 |
| 3 | env 구문 모델·파서·원문 패치·세션 | 주석·인용·중복 키·행 순서 보존과 유효/미완성 상태 전환 검증 |
| 4 | EnvEditor와 형식 정책 연결 | 공통 컴포넌트로 프로퍼티·값 두 팔레트를 구성하고, 모든 조작 경로에서 문자열·평면 구조 제약 유지 |
| 5 | 전체 입력·출력·PWA/확장·복구 검증 | 로컬 파일·폴더·첨부·중계·오프라인 재열기와 기존 형식 회귀 확인 |
| 6 | 문서·버전 정리 후 제품 코드 커밋 | 하위 호환 기능 추가로 MINOR 증가. 현재 `0.2.0` 기준이면 `0.3.0`; 커밋 시점의 실제 버전을 기준으로 결정 |

제품 코드를 커밋할 때 [package.json](../package.json), [package-lock.json](../package-lock.json)의 루트 버전, [public/version.json](../public/version.json)을 맞춘다. 앱 버전 표시는 `__APP_VERSION__`을 유지하고 생성 manifest는 직접 수정하지 않는다.

## 8. 검증 항목

- **diff:** 두 확장자·대소문자·MIME 경로, 여러 파일/hunk, 0행 구간, 추가/삭제 행 번호, 헤더와 본문 구분, 경로 공백·인용, CRLF·탭·한글·긴 줄, binary/미해석 구간, 마지막 개행 없음, 큰 파일의 렌더 비용.
- **env:** 빈 파일·빈 값·공백·주석·`export`, 따옴표 안의 `#`와 `=`, 여러 줄·이스케이프·유니코드, 숫자/불리언/null처럼 보이는 문자열, 변수 참조 원문, 중복 키·잘못된 키, 주석을 둔 추가·삭제·재정렬, 원문 패치 후 재파싱 동등성.
- **공통 캔버스:** 포인터/키보드 추가·드롭·분리/재연결·삭제, 빈 소켓과 빈 문자열 구분, env의 타입/중첩 우회 차단, 미연결 블록 복구, 공통 Undo/Redo, 문서 전환·재파싱·IME, 팬·줌·패널 폭·모바일·두 테마.
- **세션·입출력:** 원본 입력 직후 보기 전환·저장, 미완성 초안과 오류 원문의 회수, 빠른 연속 편집의 stale 응답, 저장/내보내기 실패·취소, 기존 세션 및 새 모델 복구, 변경 없는 파일의 바이트 보존.
- **회귀·빌드:** 변경 경계별 테스트 후 `npm run check`, 루트·Pages 하위 경로 산출물 검사, 실제 브라우저에서 파일 열기·저장·중계와 자산 준비 후 오프라인 재열기 확인. 계획 단계에서는 제품 검사를 실행하지 않는다.
