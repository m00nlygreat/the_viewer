# 폴더 열기 구현 계획

- 상태: 구현 전 계획. 사용자 요구와 아래의 제안 기본값을 구분한다.
- 작업 브랜치: `opening_folder`
- 기준일: 2026-11-05
- 공통 기준: [요구사항](../wiki/REQUIREMENT.md), [용어](../wiki/TERMS.md), [컴포넌트 작성 규칙](COMPONENTS.md).

## 1. 사용자 요구

1. 폴더로 전환하기 전에 열려 있는 모든 문서의 수정사항을 저장할지 묻고 정리한다.
2. 기존 파일 목록을 선택한 폴더의 파일 목록으로 교체한다.
3. 하위 폴더는 트리에서 접고 펼친다.
4. 열린 폴더 안에서 찾을 수 있는 Markdown 상대 링크와 임베드를 처리한다. 이미지는 본문에 바로 표시하고, 연결된 Markdown 문서와 Obsidian 임베드는 클릭하면 그 자리에서 접고 펼친다.

## 3. 폴더 전환과 저장

제안 흐름은 다음과 같다. 실제 목록 교체는 새 폴더를 선택하고 첫 항목 조회에 성공한 뒤 한 번만 수행한다.

```text
폴더 열기
  → 현재 편집 반영·직렬화 대기 완료
  → 수정된 문서가 있으면 저장 여부 선택
      모두 저장 → 문서별 저장 결과 확인 → 폴더 선택 버튼
      저장하지 않고 계속 → 폴더 선택 버튼
      취소 → 현재 작업 유지
  → 시스템 폴더 선택 → 루트 항목 조회
  → 마지막 변경 여부 재확인 → 복구 데이터 전환 → 목록 교체·기존 자원 정리
```

- 저장 확인에는 비활성 문서, 이메일에서 따로 연 문서, 새 문서도 포함한다. 수정된 파일명과 개수를 보여 주고 기본 초점은 `모두 저장`에 둔다.
- 저장은 [세션의 `flushDocument`와 `buildExportSnapshot`](../src/domain/session.ts)를 재사용한다. 구조 데이터의 출력 탭이 다른 형식이어도 원래 문서 형식의 작업본을 저장한다.
- 원본 핸들이 있으면 기존 바이트 비교와 쓰기 권한 확인을 거쳐 같은 파일에 쓴다. 핸들이 없는 문서는 저장 위치를 선택하고, 확장에서 받은 로컬 파일은 기존 원본 연결 절차를 제공한다.
- 저장 결과를 `저장 완료`, `다운로드 시작`, `취소`, `실패`, `사용자 동작 필요`로 구분한다. 취소·권한 거부·외부 파일 변경·출력 불가능한 구조 초안이 하나라도 남으면 전환을 멈춘다. 문법 오류가 있어도 최신 원문을 저장할 수 있는 경우에는 기존 원본 저장 규칙을 따른다.
- 브라우저 다운로드만 가능한 환경에서는 다운로드 시작을 디스크 저장 완료로 취급하지 않는다. 사용자가 파일을 확인하고 계속하는 동작을 제공하며, 확인 전에는 문서를 정리하지 않는다.
- 여러 권한 요청이나 저장 위치 선택이 필요하면 해당 파일의 버튼에서 이어서 처리한다. 비동기 저장을 반복한 뒤 자동으로 다음 시스템 선택기를 호출하지 않는다.
- 폴더 선택 취소, 첫 항목 조회 실패, 복구 저장 실패 시 기존 폴더·문서·수정사항을 유지한다. `저장하지 않고 계속`도 목록 전환이 확정될 때 적용한다. 앞서 실제 저장된 파일은 저장된 상태로 남는다.
- 저장 확인과 전환 도중에는 편집·문서 닫기·추가 전환을 막고, OS 실행·공유·확장 수신은 큐에 둔다. 폴더 선택기에서 돌아온 뒤 문서 revision이 달라졌으면 다시 저장 확인을 거친다.

폴더 선택기는 사용자 활성화가 필요하므로 일괄 저장 완료 후 새 클릭에서 호출한다. [MDN 폴더 선택 API](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)의 제약을 따른다.

## 4. 폴더 상태와 문서 세션

- 한 번에 하나의 폴더를 루트로 연다. 폴더 정보에는 ID·이름·접근 방식·루트 핸들·펼친 경로·활성 파일 경로를 둔다.
- 폴더 항목은 루트 기준 경로, 파일/폴더 종류, 필요한 접근 참조를 가진다. 목록 조회로 파일 본문을 읽거나 모든 파일의 편집 세션을 만들지 않는다.
- 열린 문서는 기존 UUID·작업본·revision·저장 기준·Undo/Redo를 유지하고 폴더 ID와 상대 경로를 추가한다. 같은 폴더 ID와 경로로 다시 접근하면 기존 세션을 사용한다. 이름이 같은 다른 경로의 파일은 다른 문서다.
- 트리의 파일 클릭과 임베드에서 사용하는 문서 조회가 같은 식별 규칙을 쓴다. 이미 편집 중인 문서의 미리보기에는 저장 전 작업본을 표시한다. 디스크에서 다시 읽어 작업본을 덮어쓰지 않는다.
- 새 폴더로 전환할 때 이전의 열린 문서 목록 전체를 정리한다. 새 폴더의 파일은 선택할 때 열고, 처음에는 파일 선택 안내를 표시한다.
- 폴더 모드에서 추가로 받은 파일은 먼저 루트 핸들의 `resolve` 등으로 폴더 소속을 확인한다. 폴더 안의 파일은 트리 항목과 연결한다. 루트 밖의 파일·새 문서·첨부는 보조 목록에 표시하는 것을 기본안으로 한다.
- 보조 목록의 문서도 다음 폴더 전환의 저장 확인에 포함한다. 폴더 닫기는 같은 저장·정리 절차를 거쳐 일반 파일 목록 모드로 돌아간다.

## 5. 파일 트리

- 사이드바와 명령 메뉴에 `폴더 열기`를 제공하고, 루트 이름 아래에 트리를 표시한다. 루트는 펼치고 하위 폴더는 접힌 상태로 시작한다.
- 폴더 클릭은 접기·펼치기, 지원 파일 클릭은 기존 문서 편집기로 열기다. 파일의 수정 표시와 현재 선택을 경로 기준으로 연결한다. 문서를 닫아도 디스크의 파일 항목은 트리에 남는다.
- 기본 정렬은 폴더 우선, 이름순이다. 숨김 항목을 포함한 실제 파일·폴더를 표시하고, 지원하지 않는 파일은 식별할 수 있게 남긴다. 이미지 항목은 읽기 전용 미리보기를 제공한다.
- 네이티브 폴더 접근에서는 폴더를 처음 펼칠 때 바로 아래 항목만 읽고 결과를 캐시한다. 닫힌 하위 폴더까지 재귀 파싱하지 않는다.
- 빈 폴더, 사라진 파일, 읽기 권한 실패를 항목 단위로 처리한다. `새로고침`은 목록을 다시 조회하되 편집 중인 문서를 자동 교체하지 않는다.
- `tree`/`treeitem`/`group`, `aria-expanded`, 하나의 이동 초점을 제공한다. 위·아래는 항목 이동, 오른쪽은 펼치기·자식 이동, 왼쪽은 접기·부모 이동, Enter는 열기를 수행한다.
- 좁은 화면과 접힌 사이드바에서 폴더 탐색 진입을 제공한다. 트리를 펼치면서 본문 폭이나 전역 스크롤이 늘어나지 않게 한다.

## 6. 상대 경로와 Markdown·Obsidian 표시

### 6.1 공통 경로 해석

- 일반 Markdown 상대 경로는 **링크를 담은 문서의 디렉터리**를 기준으로 한다. 펼친 문서 안에서는 그 문서의 위치로 기준을 바꾼다.
- `/`로 시작하는 로컬 경로는 선택한 폴더 루트 기준으로 해석하는 것을 기본안으로 한다. `./`, `../`, 한글·공백·퍼센트 인코딩, 파일 경로와 fragment를 구분해 처리한다.
- URI의 실제 구분자를 먼저 파싱하고 경로 구간을 한 번만 디코딩한 뒤 정규화한다. 인코딩된 `#`, `?`가 파일명에 있는 경우와 실제 fragment/query를 구분한다.
- 루트 밖으로 나가는 경로, 다른 드라이브·UNC·`file://` 절대 경로는 로컬 파일 조회에 사용하지 않는다. 외부 HTTP(S) 링크는 기존 링크 동작을 따른다. 찾지 못한 로컬 경로를 PWA 서버 URL로 보내지 않는다.
- 일반 Markdown 경로가 없다고 이름이 비슷한 파일을 대신 열지 않는다. 누락·모호함·권한 오류는 해당 링크 또는 임베드 위치에 표시한다.
- 현재 문서의 `#제목`은 문서 안으로 이동한다. 다른 Markdown 문서의 fragment는 해당 제목·블록을 펼치는 데 사용한다.

### 6.2 사용자에게 보이는 동작

| 표기 | 표시와 클릭 동작 |
| --- | --- |
| `[문서](../guide/start.md)` | 링크를 클릭하면 해당 위치에 문서 본문을 펼친다. 다시 접을 수 있다. |
| `![설명](../images/map.png)` | 경로를 찾으면 이미지를 바로 표시한다. |
| `![문서](../guide/start.md)` | Markdown 문서 임베드로 해석하고 클릭하면 본문을 펼친다. |
| `![[guide/start]]`, `![[guide/start.md]]` | Obsidian 문서 임베드로 표시하고 클릭하면 본문을 펼친다. |
| `![[start#제목]]`, `![[start#^block-id]]` | 클릭하면 지정한 제목 구간 또는 블록을 펼친다. |
| `![[images/map.png]]` | 로컬 이미지로 바로 표시한다. 이미지 크기 표기도 해석한다. |

- 일반 Markdown의 인라인 링크·참조형 링크·이미지가 같은 경로 해석을 사용한다. 펼치기 상태는 해당 문서와 원문 범위에 연결하고, 같은 대상이 여러 곳에 있어도 각각 접고 펼친다. 펼치기·접기는 원문과 Undo 이력을 바꾸지 않는다.
- 펼친 본문은 읽기용 미리보기다. 원문 편집은 해당 파일을 트리에서 열어 수행하고, 열린 작업본 변경은 펼친 내용에도 반영한다.
- Obsidian의 확장자 생략·폴더 경로·표시명/이미지 크기·제목/블록 참조를 별도로 파싱한다. `[[문서]]` 링크도 같은 대상 찾기와 펼치기 처리를 사용한다. 코드·코드 펜스·YAML frontmatter 내부의 문자는 링크로 해석하지 않는다.
- Obsidian에서 명시한 `./`, `../`는 문서 기준, 루트에서의 정확한 경로는 루트 기준으로 찾는다. 짧은 이름은 폴더 전체에서 일치하는 항목이 유일할 때만 결정한다. 같은 이름이 여러 개면 후보 경로를 표시해 사용자가 선택하게 한다.
- 짧은 이름을 찾는 데 필요한 전체 인덱스는 파일 본문 없이 이름·경로만 수집한다. 네이티브 접근은 필요할 때 취소 가능한 탐색을 수행한다. 탐색 실패로 인덱스가 불완전하면 유일하다고 단정하지 않는다.
- 제목은 해당 제목부터 다음 같은 수준 또는 상위 제목 전까지, 블록은 Obsidian 블록 식별자 범위로 표시한다. fragment가 없거나 찾지 못한 경우를 구분하고, 찾지 못한 fragment를 전체 문서로 조용히 대체하지 않는다.
- 중첩 임베드에도 같은 규칙을 적용한다. 조상에 같은 파일·fragment가 있으면 순환 안내를 표시하고, 기본 중첩 한도는 8단계로 제안한다.
- Obsidian 임베드의 첫 구현 대상은 Markdown 문서·제목·블록과 로컬 이미지로 구체화한다. 다른 첨부 형식은 클릭 시 파일 정보와 기존 뷰어 열기 또는 다운로드를 펼쳐 제공하는 것을 기본안으로 한다.

Obsidian 표기의 기준은 [공식 임베드 문법](https://obsidian.md/help/embeds)과 [공식 내부 링크 문법](https://obsidian.md/help/links)이다. 접힌 상태로 시작하고 클릭해 펼치는 동작은 이 프로젝트의 사용자 요구다.

### 6.3 편집기·자원 연결

- 경로 해석과 파일 읽기를 UI에서 분리한다. [Markdown 편집기](../src/features/MarkdownEditor.tsx)에서 [CodeEditor](../src/components/CodeEditor.tsx)와 미리보기에 문서 위치·대상 조회·펼치기 콜백을 전달한다.
- 라이브 미리보기와 Markdown 표 안의 링크, 펼친 문서의 렌더링이 같은 규칙을 사용하게 한다. CodeMirror의 활성 행 원문 편집·선택·IME와 클릭 이벤트가 충돌하지 않게 한다.
- 상대 경로로 찾은 로컬 이미지는 앱이 만든 Blob URL로 표시한다. HTML 정화를 유지하고 임의의 HTML `src`나 외부 이미지를 일괄 허용하지 않는다. SVG는 로컬 이미지 표시 경로에 맞게 정제한다.
- 이미지는 보이는 영역부터 읽고 파일별 크기 제한을 적용한다. Blob URL과 비동기 읽기는 문서·폴더 수명에 연결한다. 폴더 전환·위젯 제거 시 해제하고, 뒤늦은 결과를 이전 위젯에 적용하지 않는다.
- 이미지 로드와 문서 펼치기·접기 후 CodeMirror의 높이를 재측정한다. 표시 위치와 클릭 위치가 어긋나지 않는지 확인한다.

## 7. 복구와 전환 일관성

- [복구 쓰기 큐](../src/platform/documentWriteQueue.ts)를 비운 뒤 이전 문서 제거와 새 폴더 메타데이터 저장을 같은 IndexedDB 트랜잭션으로 처리한다. 기존 `clearDocuments`는 공유 티켓도 지우므로 폴더 전환 정리 용도로 그대로 호출하지 않는다.
- 트랜잭션 성공 전에는 메모리의 문서·트리를 버리지 않는다. 성공 후 이전 문서의 이력, 파싱 타이머·요청, 편집기 상태, Blob 자원을 정리한다.
- 폴더 세대 번호를 두어 전환 이전에 시작한 파일 열기·트리 조회·파싱·임베드 응답이 새 상태를 덮어쓰지 못하게 한다. 전환 중 받은 외부 입력은 완료·취소 후 해당 상태에서 처리한다.
- 복구 사용 시 루트 핸들·문서의 폴더 소속·펼친 경로·활성 경로를 보관한다. 저장된 핸들의 읽기 권한을 다시 확인하고, 필요하면 `폴더 다시 연결` 버튼으로 권한을 요청한다. 편집 작업본은 권한이 없어도 복원한다.
- 복구가 꺼져 있으면 폴더 전체 파일을 따로 저장하지 않는다. 이전 폴더 기록이 다시 살아나지 않도록 전환 시 오래된 메타데이터도 정리한다.
- 폴더 파일 목록과 별개로 현재 문서의 저장 기준 바이트를 유지한다. 외부 수정이 감지된 파일을 저장할 때는 기존 충돌 방지 규칙을 사용한다.

핸들은 IndexedDB에 저장할 수 있지만 세션 사이에 권한이 유지된다고 보장할 수 없다. [Chrome 파일 접근 API 문서](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)의 핸들 저장·권한 확인 절차를 따른다.

## 8. 브라우저 지원

- `showDirectoryPicker`가 있으면 핸들 기반으로 폴더 탐색과 원본 저장을 제공한다. 읽기 권한으로 열고 쓰기는 저장 동작에서 요청하는 것을 기본안으로 한다.
- 미지원 환경에서는 폴더 선택 input과 `webkitRelativePath`로 트리를 구성한다. 파일 바이트는 항목을 열거나 이미지를 표시할 때 읽는다. 반환된 목록에 없는 빈 하위 폴더는 표시할 수 없고, 새로고침 후 파일 접근에는 재선택이 필요하다.
- 이 대체 경로에는 원본 쓰기 핸들이 없으므로 기존 파일 출력 절차를 사용한다. 폴더 선택 input 자체도 지원하지 않으면 기존 파일 열기를 제공한다.
- 사용자가 선택한 로컬 폴더의 처리는 PWA에서 수행한다. 확장으로 들어온 파일에 폴더 접근 권한이 있다고 추정하지 않는다.

폴더 input의 반환 구조는 [MDN `webkitdirectory`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)를 기준으로 한다. API 존재 여부로 기능을 판별하고 실제 지원 브라우저에서 취소·권한·빈 폴더를 확인한다.

## 9. 구현 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 문서 ID 기반 저장 함수와 전환 제어 | 비활성 문서까지 모두 저장한다. 실패·취소·미완료 다운로드가 있으면 전환하지 않는다. 다른 출력 형식을 선택한 문서도 원래 형식으로 저장한다. |
| 2 | 폴더 접근·상태·복구와 목록 교체 | 루트 조회 성공 뒤 기존 목록을 한 번 교체한다. 실패·취소 시 기존 작업을 유지한다. 같은 경로의 열린 파일을 중복 생성하지 않는다. |
| 3 | 사이드바 트리 | 다단계·빈 폴더를 접고 펼치며 포인터·키보드로 파일을 연다. 큰 폴더에서도 파일 본문 전체를 선행 로드하지 않는다. |
| 4 | 상대 링크와 이미지 | 서로 다른 깊이의 문서, 한글·공백 파일명, `../`, 루트 경로와 누락 파일을 처리한다. 로컬 이미지는 바로 표시한다. |
| 5 | Markdown·Obsidian 펼치기 | 일반 `.md` 링크와 임베드, 확장자 생략, 제목·블록 참조를 클릭해 펼친다. 중첩 상대 경로, 중복 이름, 순환 참조, 작업본 갱신을 처리한다. |
| 6 | 통합 확인과 버전 동기화 | 재실행·권한 재요청·대체 폴더 선택·외부 수신·복구 큐 경합, 모바일·다크 화면과 편집 위치를 확인한다. 기능 커밋 전에 SemVer MINOR를 올린다. |

검증은 전환과 경로 해석의 실제 실패 조건을 중심으로 한다. 저장 중 일부 성공 후 나머지 실패, 선택기 취소, 외부 변경 충돌, 대기 중 복구 쓰기, 이전 폴더의 늦은 응답을 회귀 사례로 둔다. 순수 경로·참조 해석과 세션 전환은 자동 검사하고, 브라우저 권한·선택기·트리 키보드·CodeMirror 높이·IME는 실제 화면에서 확인한다.

각 단계에서 관련 린트·앱 타입 검사·영향받는 회귀 검사를 수행하고, 통합 후 PWA 빌드와 배포 base를 확인한다. 새 플랫폼 파일이 들어오면 [앱 타입 검사 설정](../tsconfig.app.json)과 [명령 설정](../package.json)의 검사 범위도 갱신한다. 제품 커밋 시 현재 `0.1.2`에서 `0.2.0`으로 올리고 패키지·잠금 파일·공개 버전 파일을 함께 맞춘다.
