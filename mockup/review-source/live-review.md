## 키보드 관찰의 한계

시간 체크 해제 뒤 Escape를 보냈을 때 팝오버가 닫히지 않았고, 빈 캔버스를 클릭한 뒤 Ctrl+Z를 보냈을 때도 값 복원을 확인하지 못했다. 도구의 초점 보고는 주소창을 가리켜 실제 키 이벤트의 수신 대상을 확정할 수 없었다. 따라서 이 두 시도를 앱 키보드 결함의 확정 증거나 키보드 검수 통과로 취급하지 않는다.

별도로 [원본 로직](editor.logic.js.txt)의 `mainKeyDown`은 INPUT/TEXTAREA/contenteditable 대상이면 먼저 반환한다. 날짜 입력에는 별도 Escape 핸들러가 없다. “날짜 입력에 초점이 있어도 Esc로 닫힘”을 검증된 원본 동작으로 쓰지 말고, 제품에서는 기존 입력 요소의 키보드 대응으로 명확히 연결해야 한다. 즉시 반영한 값을 되돌리는 동작과 팝오버 닫기를 구별하며 새 푸터를 추가하지 않는다.

## 도구 제약과 남은 범위

- iframe 하단이 창 밖에 있을 때 접근성 인덱스로 Undo를 누르려는 두 시도는 창 경계 밖 좌표 오류로 끝났다. 이후 바깥 페이지를 스크롤하고 새 화면의 실제 버튼 좌표로 눌러 L07을 확인했다. 실패한 시도를 목업 버튼의 기능 오류로 기록하지 않는다.
- 드롭 오류를 확인한 뒤 마지막 새로고침 버튼을 누르려는 단계에서 컴퓨터 사용 도구가 현재 브라우저 URL을 식별하지 못해 조작을 차단했다. 이후 브라우저 입력이나 다른 브라우저 자동화를 진행하지 않았다. 마지막 새로고침 실행·초기 상태 복원은 완료를 확인하지 못했다.
- 두 번째 케이스 시트의 로딩·상단 제목은 확인했지만, 그 안의 8개 사례군을 이번에 각각 클릭해 검수하지 못했다. [마크업](case-sheet.markup.html)·[로직](case-sheet.logic.js.txt)·기존 참고 이미지에 근거한 분석과 구분한다.
- 실제 블록 이동·분리·연결의 성공 경로, 드래그 도중 고스트/삽입선의 활성 프레임, 일반 값·이름 편집, 가져오기, 출력 복사, 키보드·IME, 오른쪽/키보드 리사이저, Ctrl/Meta+wheel, Space/가운데 버튼 팬, 핀치·모바일은 이번 직접 검수에서 확인하지 않았다.
- 직접 확인된 팬·확대·날짜·출력·왼쪽 리사이저를 제외한 모든 상태가 작동한다고 일반화하지 않는다. 원본 HTML·추출 로직·제품 코드는 수정하지 않았다.

## 계획에 반영할 내용

1. [GOAL](../../GOAL.md)의 검토 상태를 소스 분석만 수행한 상태에서 위 직접 확인 범위를 포함한 상태로 갱신한다.
2. 드롭 종료 결함은 소스 실행과 실제 목업 양쪽에서 재현된 구현 필수 수정 항목으로 둔다. 블록 드래그 기능 자체를 생략하거나 클릭 추가로 대체하지 않는다.
3. 날짜의 즉시 반영·시간대 비활성·빈 곳 클릭 닫기·버튼 Undo 복원을 근거에 추가한다. 날짜 입력 Escape는 연결할 키보드 동작과 미확인 결과를 구분한다.
4. 팬·격자·블록의 공통 변환, 120% 확대·100% 복원·기본 맞춤, 왼쪽 리사이저 드래그·더블클릭 복원을 직접 확인한 계약으로 표시한다.
5. 8개 사례군 전체의 직접 조작 검수와 D01–D06 결정 항목은 미완료로 유지한다. 이번 관찰로 원본에 없는 메뉴 트리거·정적 컨트롤의 callback을 확정하지 않는다.
