# LOG

프로젝트 관련 중대 결정사항, 새로 알아낸 사실, 방향 변경을 시간순으로 기록한다.

## 2026-10-30

- Markdown 모델은 원문 문자열만 담으므로 편집마다 별도 파일 파싱을 기다릴 필요가 없다. 입력 즉시 모델을 동기화해 대기 상태 띠로 인한 레이아웃 흔들림을 막고, Markdown 미리보기는 선택·뷰포트 변경만으로 전체 장식을 다시 계산하지 않도록 한다.
- 표 편집을 열면 그리드에 포커스를 주고 Glide 자동 폭 측정으로 셀 내용에 맞춰 컬럼을 표시한다. 표 셀의 줄바꿈은 Markdown 행을 깨뜨리지 않도록 공백으로 정규화한다.
- CodeMirror 안의 표 위젯을 `contenteditable=false`로 분리하고 렌더가 끝난 두 프레임 뒤 그리드에 포커스를 준다. 편집 중 Enter가 CodeMirror로 새어 나가면 가로채 그리드로 포커스를 돌려 문서에 새 줄이 삽입되지 않게 한다.

## 2026-10-29

- Markdown 표는 보기에서 일반 표로 렌더하고 `표 편집`을 시작하면 Glide 그리드로 교체한다. 그리드 변경은 표 블록만 Markdown 원문으로 직렬화해 반영하며 정렬 정보와 수정하지 않은 셀 구문을 보존한다.
- Markdown 보기의 블록별 입력 패널을 CodeMirror 6 연속 편집기로 바꿨다. 세션의 Markdown 문자열을 기준 데이터로 유지하고, GFM Lezer 트리·Decoration으로 활성 문법 블록은 원문, 비활성 영역은 서식으로 표시한다. 체크리스트는 원문 표식만 바꾸며 미지원 구문은 원문 편집을 유지한다.
- 보기·모바일 원본 CodeMirror의 줄바꿈 보존, 다중 외부 변경 위치 매핑, IME 중 외부 변경 병합, 탭 복원 시 선택·스크롤 복원을 보강했다. 위험한 링크와 미지원 블록·컨테이너 문법은 표식을 숨기지 않고 원문으로 유지한다. 원문 보존·왕복 편집·Undo/Redo·내보내기·IME 병합 회귀 테스트를 추가했다. PWA 린트·타입 검사·36개 테스트와 루트·Pages 하위 경로 빌드 검사가 통과했다. Windows 브라우저 URL을 Computer Use가 안전하게 판별하지 못해 실제 시각·클릭 입력과 한글 IME 수동 확인은 남았다.
- 배포 화면 피드백을 반영해 Markdown 보기의 자동 줄바꿈과 편집 중인 블록·현재 행 강조를 추가했다. 비활성 코드 블록에는 시작·끝 경계를 표시하며 모든 시각 효과는 Decoration으로 적용해 문서 원문을 바꾸지 않는다. PWA 전용 검사·39개 테스트·루트 및 Pages 하위 경로 빌드가 통과했고 [Actions #17](https://github.com/m00nlygreat/the_viewer/actions/runs/40745860680)에서 배포를 완료했다.
- 원본 탭에서 Monaco가 짧은 CSS hex 색상을 토큰 색으로 거부하는 오류를 확인했다. 테마 색상은 Monaco가 받기 전에 정규화하고 `#fff`·유효한 전체 hex·잘못된 값의 fallback 회귀 테스트를 추가했다. PWA 전용 42개 테스트·빌드가 통과했고 [Actions #19](https://github.com/m00nlygreat/the_viewer/actions/runs/40849188214) 배포 후 SourceEditor 청크 해시가 공개 빌드와 일치함을 확인했다.
- CSV 원본의 plain text 가독성을 보완하기 위해 감지 구분자·인용 문자열·이스케이프 따옴표를 강조하고, 각 열 값에 8색 순환 팔레트를 적용한다. 데스크톱 Monaco와 모바일 CodeMirror가 여러 줄 인용 필드와 행별 색 초기화를 동일하게 처리하며 구문 강조는 원문을 바꾸지 않는다. PWA 전용 린트·타입 검사, 6개 파일 46개 테스트와 두 경로 빌드가 통과했다. [Actions #40856256616](https://github.com/m00nlygreat/the_viewer/actions/runs/40856256616) 배포 후 공개 편집기 청크·색상 CSS가 200으로 응답하고 CSV 열 색 토큰을 포함함을 확인했다.

## 2026-10-28

- Chrome 확장은 파일 감지·읽기·중계 전용으로 줄이고 PWA가 보기·편집·내보내기·복구를 맡도록 구조를 바꾼다. 파일 본문은 확장 IndexedDB의 10분 티켓으로 저장하고 PWA가 프로토콜 v1 청크 메시지로 요청한다. PWA 저장 후 티켓을 지우며, 기존 확장 작업은 원본을 남긴 채 문서별로 복원한다.
- 파일을 여는 과정의 진행 문구·다이얼로그·완료 알림을 제거하고, 실패할 때만 비모달 상태와 재시도를 제공한다.
- 배포는 PWA를 먼저 Pages에 올린 뒤 실제 Chrome 연결과 수신을 확인하고, 수동 Pages workflow로 확장 ZIP을 추가한다. 오프라인 전달은 PWA 서비스 워커 캐시가 준비된 뒤 가능하다.
- EML·CSV·Markdown·ICS·VCF의 HTTP(S) 최상위 GET 응답을 기본 자동 열기로 제공하며, 설치 시 HTTP(S) 전체 사이트 접근 권한을 요청한다. 응답 MIME·URL 파일명·응답 파일명을 함께 확인하고 HTML 응답은 건드리지 않는다. 응답 확인 뒤 본문을 다시 GET하므로 서버에서 두 번 처리될 수 있음을 안내한다.
- [Tourmaline 확장 구현](https://github.com/m00nlygreat/tourmaline-chrome/blob/e5c92609e92298b3ab0368f44581ce2c20bef13c/src/extension/manifest.json)을 확인해 일반 MV3 확장에서도 Chrome으로 연 로컬 파일을 처리할 수 있음을 확인했다. 로컬 지원 파일의 `file://` 탐색을 DNR로 뷰어에 전달한다. Chrome의 파일 URL 접근 승인이 한 번 필요하며, 새 탭 강제 교체는 사용하지 않는다.
- 사용자 요청에 따라 상위 탭을 `보기 / 원본`으로 통합했다. 문서별 작업본·Undo/Redo, 최신 revision 파싱, 보기 편집과 원본 편집을 연결하고 데스크톱 Monaco·모바일 CodeMirror를 적용했다. PWA 전용 검사·배포 workflow로 분리했으며 확장 검증은 사용자 요청에 따라 실행하지 않는다.
- PWA 전용 린트·타입 검사·17개 테스트와 루트·Pages 하위 경로 빌드 검사를 통과해 `8fda65b`를 `main`에 배포했다. [GitHub Pages](https://m00nlygreat.github.io/the_viewer/) 공개 응답과 Monaco·Worker 서비스 워커 캐시를 확인했다. 화면 시각·오프라인 수동 확인과 Chrome 확장 검증은 별도 확인 항목이다.

## 2026-10-21

- 모바일 페이지 확대를 잠그고, 문서 보기 영역 안의 Ctrl+휠·핀치 동작만 앱 확대에 사용한다. 편집기에는 문서 확대를 적용하지 않는다.
- CSV 표를 Glide Data Grid로 교체해 캔버스 가상화, 범위 선택, 다중 셀 붙여넣기와 채우기를 지원한다. 파싱·문자열 보존·출력은 기존 CSV 코어를 유지하고, React 19 호환 `6.0.4-alpha24`를 고정했다.
- 명령 메뉴의 형식별 파일 열기 항목을 단일 파일 열기로 통합하고, 형식별 새 파일 만들기는 유지한다.

## 2026-10-19

- 위키 관리 범위를 LOG, TERMS, REQUIREMENT로 정했다. 현재 작업 폴더에서 제품 설명이나 요구사항 자료를 찾지 못해 세부 내용은 확인 후 확정하기로 했다.
- 제품을 텍스트 기반 파일 뷰어로 정의하고, Chrome 확장 프로그램과 GitHub Pages 배포 PWA로 제공하며 데스크톱·모바일을 지원하기로 했다. 초기 대상 형식은 `.eml`, `.csv`, `.md`, `.ics`다.
- 초기 지원 형식에 연락처 카드 파일 `.vcf`도 포함하기로 했다.
- 읽기와 렌더링뿐 아니라 파일 편집 기능도 제품 요구사항에 포함하기로 했다. 형식별 편집 범위와 저장 방식은 후속 결정 사항이다.
- 컴포넌트 작성 기준을 [작성 규칙](../docs/COMPONENTS.md)에 정리했다. PWA·확장 프로그램의 공통 UI를 공유하고 파일 처리와 플랫폼 API를 UI에서 분리한다.
- [기준 목업](../mockup/The%20Viewer.html)을 보관하고 프론트엔드 작업에서 디자인 속성·수치·배치를 그대로 준수하도록 정했다. 목업에는 다크·라이트의 데스크톱·모바일 기준 화면 12개가 있다.
- 당시 다섯 형식의 편집·내보내기, 원본 보존, 로컬 복구, PWA 설치·오프라인, Manifest V3 확장, 단계별 검증·완료 조건을 별도 구현 계획에 정리했다. 계획 수립과 앱 구현이 분리된 상태였다.
- 빌드 출력은 PWA `./dist/app`, Chrome 확장 `./dist/chrome_extension`으로 고정하고, GitHub Pages는 Actions에서 `./dist/app`의 내용만 배포하기로 했다.
- 목업의 `원본`은 현재 작업본의 원시 텍스트 모드로 정의하고, 불러온 바이트 백업은 내부에서 따로 보존하도록 계획했다. 형식별 미지원 구조와 권한 거절에도 원문 회수와 일반 파일 입출력 경로를 유지한다.
- React·TypeScript 공통 UI와 CSV·EML·Markdown·ICS·VCF 처리 코어, PWA·MV3 확장 빌드, 로컬 복구·서비스 워커, CI를 구현했다. 두 타깃 검사·테스트·빌드와 npm 보안 감사(취약점 0건)를 확인했다.
- `m00nlygreat/the_viewer` 원격 저장소의 `main`에 코드를 푸시하고 Pages를 Actions 빌드 방식으로 활성화했다. PWA URL은 [GitHub Pages](https://m00nlygreat.github.io/the_viewer/)이며 workflow는 `dist/app`만 올린다.
- Chrome 확장 폴더와 ZIP을 빌드해 소스 커밋에 포함했다. 요청 범위에 따라 Chrome Web Store에는 게시하지 않는다.
- 배포 앱에서 시작 화면과 새 CSV 진입을 확인해 빈 CSV의 자동 구분자 진단을 제거하고 회귀 검사를 추가했다. 목업 파일은 수정하지 않았으며 브라우저 보안 제한으로 목업 자체 렌더 비교와 설치 후 오프라인·실제 확장 설치 검증은 남아 있다.
