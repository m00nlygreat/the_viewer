# LOG

프로젝트 관련 중대 결정사항, 새로 알아낸 사실, 방향 변경을 시간순으로 기록한다.

## 2026-10-21

- 모바일 페이지 확대를 잠그고, 문서 보기 영역 안의 Ctrl+휠·핀치 동작만 앱 확대에 사용한다. 편집기에는 문서 확대를 적용하지 않는다.

## 2026-10-19

- 위키 관리 범위를 LOG, TERMS, REQUIREMENT로 정했다. 현재 작업 폴더에서 제품 설명이나 요구사항 자료를 찾지 못해 세부 내용은 확인 후 확정하기로 했다.
- 제품을 텍스트 기반 파일 뷰어로 정의하고, Chrome 확장 프로그램과 GitHub Pages 배포 PWA로 제공하며 데스크톱·모바일을 지원하기로 했다. 초기 대상 형식은 `.eml`, `.csv`, `.md`, `.ics`다.
- 초기 지원 형식에 연락처 카드 파일 `.vcf`도 포함하기로 했다.
- 읽기와 렌더링뿐 아니라 파일 편집 기능도 제품 요구사항에 포함하기로 했다. 형식별 편집 범위와 저장 방식은 후속 결정 사항이다.
- 컴포넌트 작성 기준을 [작성 규칙](../docs/COMPONENTS.md)에 정리했다. PWA·확장 프로그램의 공통 UI를 공유하고 파일 처리와 플랫폼 API를 UI에서 분리한다.
- [기준 목업](../mockup/The%20Viewer.html)을 보관하고 프론트엔드 작업에서 디자인 속성·수치·배치를 그대로 준수하도록 정했다. 목업에는 다크·라이트의 데스크톱·모바일 기준 화면 12개가 있다.
- [구현 계획](../GOAL.md)에 다섯 형식의 편집·내보내기, 원본 보존, 로컬 복구, PWA 설치·오프라인, Manifest V3 확장, 단계별 검증·완료 조건을 정리했다. 당시에는 계획 수립과 앱 구현이 분리된 상태였다.
- 빌드 출력은 PWA `./dist/app`, Chrome 확장 `./dist/chrome_extension`으로 고정하고, GitHub Pages는 Actions에서 `./dist/app`의 내용만 배포하기로 했다.
- 목업의 `원본`은 현재 작업본의 원시 텍스트 모드로 정의하고, 불러온 바이트 백업은 내부에서 따로 보존하도록 계획했다. 형식별 미지원 구조와 권한 거절에도 원문 회수와 일반 파일 입출력 경로를 유지한다.
- React·TypeScript 공통 UI와 CSV·EML·Markdown·ICS·VCF 처리 코어, PWA·MV3 확장 빌드, 로컬 복구·서비스 워커, CI를 구현했다. 두 타깃 검사·테스트·빌드와 npm 보안 감사(취약점 0건)를 확인했다.
- `m00nlygreat/the_viewer` 원격 저장소의 `main`에 코드를 푸시하고 Pages를 Actions 빌드 방식으로 활성화했다. PWA URL은 [GitHub Pages](https://m00nlygreat.github.io/the_viewer/)이며 workflow는 `dist/app`만 올린다.
- Chrome 확장 폴더와 ZIP을 빌드해 소스 커밋에 포함했다. 요청 범위에 따라 Chrome Web Store에는 게시하지 않는다.
- 배포 앱에서 시작 화면과 새 CSV 진입을 확인해 빈 CSV의 자동 구분자 진단을 제거하고 회귀 검사를 추가했다. 목업 파일은 수정하지 않았으며 브라우저 보안 제한으로 목업 자체 렌더 비교와 설치 후 오프라인·실제 확장 설치 검증은 남아 있다.
