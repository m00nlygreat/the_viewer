# 요구사항 요약

사용자 요청과 기준 목업에 따른 현재 요구사항이다. 상세 구현 순서와 완료 조건은 [구현 계획](../GOAL.md)에 둔다.

## 1. 제품 목표

- 텍스트 기반 파일을 브라우저에서 읽기 쉽게 렌더링하고, 편집한 내용을 실제 파일로 내보내는 도구.

## 2. 사용자

- 데스크톱과 모바일에서 이메일, 일정, 표, 문서 등 텍스트 파일을 빠르게 확인하거나 편집하려는 사용자.

## 3. 주요 기능

- 공통 React UI와 파일 처리 코어를 공유하는 Chrome 확장 프로그램과 GitHub Pages 배포 PWA로 제공한다.
- 데스크톱과 모바일 화면에 대응한다.
- `.eml`, `.csv`, `.md`, `.ics`, `.vcf`의 보기·편집·원본·내보내기를 제공한다.
- 파일 선택·다중 드롭·붙여넣기, 열린 파일 전환, 명령 검색, 실행 취소·되돌리기, 로컬 작업 복구를 제공한다.
- CSV 표 검색·필터·정렬, EML 본문·헤더·첨부, Markdown 서식, ICS 반복·시간대, VCF 반복 필드·다중 연락처를 처리한다.
- 지원하는 이메일 첨부는 새 작업 문서로 열고, 다른 첨부는 내려받는다.
- PWA 설치·오프라인 편집·업데이트를 지원한다. OS 파일 연결·공유 수신은 지원 환경에서 제공하고 일반 파일 선택을 함께 유지한다.
- Chrome 확장은 전용 탭·도구모음·링크 메뉴로 진입하며, URL 파일 접근에는 대상 사이트의 선택적 권한을 사용한다.

## 4. 공통 UX 원칙

- [기준 목업](../mockup/The%20Viewer.html)의 12개 화면에 있는 디자인 속성·수치·배치·세부 상태를 반드시 준수한다.
- 목업에 없는 화면·상태만 기존 스타일을 이어서 설계한다.
- 시스템·라이트·다크 테마와 데스크톱·모바일 반응형을 제공한다.
- 파일 파싱·편집은 기기 내부에서 수행하고, 원본 바이트와 현재 작업본을 분리해 보존한다.
- 파일 본문·첨부를 자동 업로드하지 않으며 HTML·Markdown의 위험한 내용과 외부 자원 요청을 제어한다.
- 편집·내보내기·복구의 실패와 취소를 처리하고, 손상된 작업본도 회수 가능하게 한다.

## 5. 빌드·배포

- PWA는 `./dist/app`, Chrome 확장은 `./dist/chrome_extension`으로 빌드한다.
- GitHub Pages는 Actions로 `./dist/app`의 내용만 배포한다.
- 두 타깃의 빌드가 서로의 산출물을 삭제하지 않아야 한다.
- 저장소 하위 경로와 루트 배포에 맞춰 자산·manifest·서비스 워커의 base를 일치시킨다.
- 확장 폴더와 설치 가능한 ZIP을 별도로 제공한다.

## 6. 게시 단계에 연결할 정보

- 실제 GitHub 저장소·기본 브랜치·Pages 설정·사용자 도메인.
- Chrome Web Store에 공개할 경우 개발자 계정과 스토어 게시 정보.
- 구현 계획의 세부 기본값은 구현 시 검증하며, 현재 앱 구현은 미착수 상태다.
