# 요구사항 요약

사용자 요청과 기준 목업에 따른 현재 요구사항과 동작 기준이다.

## 1. 제품 목표

- 텍스트 기반 파일을 브라우저에서 읽기 쉽게 렌더링하고, 편집한 내용을 실제 파일로 내보내는 도구.

## 2. 사용자

- 데스크톱과 모바일에서 이메일, 일정, 표, 문서 등 텍스트 파일을 빠르게 확인하거나 편집하려는 사용자.

## 3. 주요 기능

- Chrome 확장은 파일 감지·읽기·중계를 담당하고, GitHub Pages PWA는 보기·편집·내보내기·작업 복구를 담당한다.
- 확장과 PWA는 프로토콜 v1의 브라우저 내부 포트 메시지와 192 KiB Base64 조각으로 파일을 전달한다. 서버에는 파일 본문을 올리지 않는다.
- 데스크톱과 모바일 화면에 대응한다.
- `.eml`, `.csv`, `.md`, `.ics`, `.vcf` 파일의 보기·편집·내보내기를 제공한다.
- 문서 탭은 `보기 / 원본` 두 개로 통합한다. 별도 편집 탭 없이 보기의 셀·블록·필드·상세 영역에서 가능한 범위를 편집한다.
- Markdown 보기는 CodeMirror 6 전체 문서 연속 편집과 라이브 프리뷰를 제공한다. 긴 줄은 편집 화면 너비에 맞춰 자동 줄바꿈한다. 리스트는 현재 편집 물리 행 하나만 원문과 편집 강조로 표시하고 나머지 행은 미리보기한다. 여러 선택·드래그 선택에서도 리스트 편집 행은 한 줄로 제한한다. 그 밖의 문법 블록은 커서·선택·IME 조합 중 원문으로 보이며, 나머지는 구문 트리 기반 Decoration으로 서식을 표시한다.
- Markdown 첫 범위는 제목·굵게·기울임·취소선·인라인 코드·링크·목록·인용·체크리스트다. 체크 동작은 `[ ]`/`[x]` 원문만 바꾼다. 표·코드 블록·이미지·frontmatter·미지원 구문은 원문을 유지해 편집할 수 있다.
- 보기와 원본은 같은 세션 Markdown 문자열·revision·Undo/Redo를 사용한다. BOM·기존 개행·미편집 구문을 유지하고 HTML에서 Markdown을 만들지 않는다.
- 원본은 현재 작업본의 전체 텍스트를 데스크톱 Monaco Editor와 모바일 CodeMirror로 표시·편집한다. 두 탭은 같은 작업본과 변경 이력을 사용하며, 원본 입력 직후 전환·내보내기에도 최신 내용을 보존한다.
- CSV 원본은 감지된 구분자와 인용 필드·이스케이프 따옴표를 구문 강조하고, 각 열 값은 8색 순환 팔레트로 구분한다. 여러 줄 인용 필드에서도 열 색을 유지하며 화면 강조가 원문을 바꾸지 않는다.
- 원본 문법 오류에서는 마지막 유효 보기를 구분하고 오래된 구조를 사용한 편집을 막는다. 입력한 원문은 수정·내보내기·로컬 복구가 가능해야 한다.
- 파일 선택·다중 드롭·붙여넣기, 열린 파일 전환, 명령 검색, 실행 취소·되돌리기, 로컬 작업 복구를 제공한다.
- 명령 메뉴의 파일 열기는 하나로 통일하고, 새 파일 만들기는 형식별로 제공한다.
- CSV 표 검색·필터·정렬·셀 범위 편집·복사/붙여넣기·채우기와 열 너비 자동 맞춤(파일을 열 때 적용), EML 지원 본문의 헤더·본문 편집, Markdown 서식, ICS 반복·시간대, VCF 반복 필드·다중 연락처를 처리한다. 안전하게 매핑할 수 없는 복합 MIME은 보기 편집을 제한하고 원본 탭을 제공한다.
- 지원하는 이메일 첨부는 새 작업 문서로 열고, 다른 첨부는 내려받는다.
- PWA 설치·오프라인 편집·업데이트를 지원한다. OS 파일 연결·공유 수신은 지원 환경에서 제공하고 일반 파일 선택을 함께 유지한다.
- 확장 도구모음과 링크 메뉴는 작은 중계 페이지를 연다. HTTP(S) 링크를 가져오기 전 대상 사이트를 확인하고, 파일 자동 열기 규칙과 파일 URL 접근 안내를 유지한다.
- 확장 티켓은 확장 전용 IndexedDB에 최대 10분 보관한다. PWA가 복원·저장한 뒤 티켓을 완료하며, 연결·파싱·저장 실패는 재시도할 수 있다.
- 파일을 여는 동안 진행 문구·다이얼로그·완료 알림을 표시하지 않는다. 실패만 비모달 오류와 재시도로 안내한다.
- 기존 확장에 저장된 작업은 편집 상태와 첨부 관계를 포함해 문서별로 이전한다. PWA 저장 확인 전 기존 저장 데이터를 삭제하지 않는다.

## 4. 공통 UX 원칙

- [기준 목업](../mockup/The%20Viewer.html)의 12개 화면에 있는 디자인 속성·수치·배치·세부 상태를 준수한다. 사용자 요청으로 변경한 두 탭과 보기 안의 편집 동작은 이 문서의 요구사항을 우선한다.
- 목업에 없는 화면·상태만 기존 스타일을 이어서 설계한다.
- 시스템·라이트·다크 테마와 데스크톱·모바일 반응형을 제공한다.
- 모바일 브라우저의 페이지 확대를 막고, 보기의 읽기 영역에서 Ctrl+휠 또는 핀치로 확대·축소한다. 보기 안의 입력과 원본 편집기의 키보드·휠·핀치 동작을 방해하지 않는다.
- 파일 파싱·편집은 기기 내부에서 수행하고, 원본 바이트와 현재 작업본을 분리해 보존한다.
- 파일 본문·첨부를 자동 업로드하지 않으며 HTML·Markdown의 위험한 내용과 외부 자원 요청을 제어한다.
- 편집·내보내기·복구의 실패와 취소를 처리하고, 손상된 작업본도 회수 가능하게 한다.

## 5. 빌드·배포

- PWA는 `./dist/app`, 중계 전용 Chrome 확장은 `./dist/chrome_extension`, ZIP은 버전별 `./dist/the-viewer-chrome-v<version>.zip`으로 빌드한다.
- GitHub Pages workflow는 PWA 전용 검사 후 `./dist/app`의 내용만 올린다. Chrome 확장 빌드와 ZIP 배포는 별도의 수동 작업으로 관리한다.
- 두 타깃의 빌드가 서로의 산출물을 삭제하지 않아야 한다.
- 저장소 하위 경로와 루트 배포에 맞춰 자산·manifest·서비스 워커의 base를 일치시킨다.
- 확장 폴더와 설치 가능한 ZIP을 별도로 제공한다.

## 6. 배포 정보와 남은 확인

- 원격 저장소: [m00nlygreat/the_viewer](https://github.com/m00nlygreat/the_viewer), 기본 브랜치 `main`.
- PWA: [GitHub Pages 배포](https://m00nlygreat.github.io/the_viewer/). Actions가 `dist/app`만 배포한다.
- Chrome 확장 ZIP은 [다운로드 페이지](https://m00nlygreat.github.io/the_viewer/downloads/the-viewer-chrome-latest.zip)에서 제공한다. Chrome Web Store 게시 범위는 아니다.
- PWA 공개 후 서비스 워커 캐시 준비 뒤에는 로컬 파일 전달을 오프라인에서 사용할 수 있다. Chrome 확장 연결·파일 전달과 ZIP 배포는 확장 검증 후 별도로 관리한다.
