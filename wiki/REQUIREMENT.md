# 요구사항 요약

사용자 요청과 기준 목업에 따른 현재 요구사항과 동작 기준이다.

## 1. 제품 목표

- 텍스트 기반 파일을 브라우저에서 읽기 쉽게 렌더링하고, 편집한 내용을 실제 파일로 내보내는 도구.

## 2. 사용자

- 데스크톱과 모바일에서 이메일, 일정, 표, 문서 등 텍스트 파일을 빠르게 확인하거나 편집하려는 사용자.

## 3. 주요 기능

- Chrome 확장은 파일 감지·읽기·중계를 담당하고, GitHub Pages PWA는 보기·편집·내보내기·작업 복구를 담당한다.
- 확장과 PWA는 프로토콜 v1의 브라우저 내부 포트 메시지와 192 KiB Base64 조각으로 파일을 전달한다. 서버에는 파일 본문을 올리지 않는다.
- 데스크톱과 모바일 화면에 대응한다.
- `.eml`은 읽기 전용 이메일 보기와 내보내기를 제공한다. `.csv`, `.md`, `.ics`, `.vcf`는 보기·편집·내보내기를 제공한다.
- JSON(`.json`), YAML(`.yaml`, `.yml`), TOML(`.toml`)을 공통 블록 편집기와 원본 보기에서 다룬다. 파싱할 수 없는 원본은 수정·회수할 수 있고 마지막 구조 보기는 잠근다.
- [구조 데이터 목업](../mockup/JSON%20%EB%B7%B0%EC%96%B4%20%EB%94%94%EC%9E%90%EC%9D%B8.html)의 편집기와 8개 사례군을 기준으로 한다. 상세 요구사항 F01–F35·N01–N10과 구현 순서는 [GOAL](../GOAL.md)에 둔다.
- 기존 공통 셸·보기/원본·파일 동작·테마·반응형을 우선한다. 블록 내부의 컨테이너·회색 프로퍼티 행·흰 값 칩은 목업의 치수·서체·색·그림자·SVG·상태를 따른다. 목업에 없는 요소를 추가하거나 일반 트리로 단순화하지 않는다.
- 공통 블록 보기에는 컨테이너·프로퍼티·값 팔레트, 추론 스키마, 자유 좌표 캔버스, JSON/YAML/TOML 출력, 점검을 둔다. 스키마는 객체 형태의 재사용이며 외부 스키마 검증 기능이 아니다.
- 행 전체와 값·컨테이너는 별도 드래그 단위다. 값만 분리하면 원래 프로퍼티는 빈 자리로 남는다. 값·컨테이너를 객체에 직접 놓으면 목업 코드처럼 key/key2… 프로퍼티로 감싸며, 배열에는 배열 자리로 넣는다. 빈 캔버스는 미연결 블록을 만든다. 문서 루트는 삭제·분리하지 않는다. 미연결 블록은 출력에서 제외한다.
- 드래그는 4px 기준·클릭 오프셋·원본 흐림·고스트·빈 소켓 강조·검은 삽입선을 유지한다. 팬은 빈 바닥 드래그·Space·가운데 버튼·wheel, 확대는 Ctrl/Meta+wheel·핀치·버튼으로 25–300%를 지원한다. 격자와 내용은 같은 좌표 변환을 쓴다. 양쪽 패널은 드래그·방향키·더블클릭 복원을 제공한다.
- 이름·값 편집, 빈 자리/null/빈 텍스트 구분, 긴 텍스트 펼침·공백·개행, 큰 수의 원문·경고, 날짜·색·링크 표시, 타입 메뉴, 접힌 요약, 많은 배열의 더 보기, 깊은 경로·단독 보기를 구현한다. 이름·숫자·날짜·색 원문을 표시 때문에 자동 변경하지 않는다.
- 목업의 가져오기는 JSON으로 현재 루트를 교체하고, 내보내기는 선택 형식을 클립보드에 복사한다. 기존 앱의 파일 내보내기와 구분해 연결한다. 출력 탭은 문서 형식을 바꾸지 않는다. 점검은 상태명·경로/개수를 표시한다.
- TOML 객체의 null은 목업처럼 출력에서 제외하고 경로를 안내하며 원본은 유지한다. 별도 생략 선택 UI는 추가하지 않는다. 빈 자리·표현 불가 값의 화면 표식을 유효한 파일로 복사하지 않는다. YAML/TOML은 실제 파서를 쓰고 큰 수·날짜 종류·원문을 보존한다. 임의의 문자열 변환·구문 삭제·전체 읽기 전용으로 지원을 축소하지 않는다.
- 구조/원본 편집은 기존 문서 세션·공통 이력·로컬 복구에 연결한다. 미완성 구조 초안과 원문 문법 상태를 구분하고, 취소·오래된 파싱 응답·내보내기 실패가 데이터를 손상시키지 않게 한다.
- 단일 값 편집은 유효한 원문 범위가 있으면 해당 토큰만 바꿔 다른 공백과 주석을 보존한다. 구조 변경이나 사용할 수 없는 범위는 재직렬화하며 이전 범위를 폐기한다. TOML의 정수·실수 범위와 유니코드 제약 때문에 표현할 수 없는 값은 복사·파일 출력하지 않는다.
- 값 표면의 보조 클릭 또는 Shift+F10으로 타입 메뉴를 연다. 이는 정적 목업에 진입 동작이 없어 연결한 방식이다. 긴 키는 최대 160px에서 말줄임한다. 100개를 넘는 배열은 앞 3개와 마지막 항목 사이에 더 보기를 표시한다.
- 공통 헤더의 `출력 복사`는 선택한 미리보기 형식을 복사하고, `내보내기`는 선택한 형식의 파일을 만든다. 다른 형식으로 내보내도 열린 문서와 저장 기준은 변경하지 않는다. YAML의 앵커·참조, 사용자 태그, 복수 문서, 비문자열 키는 원본을 보존하기 위해 구조 편집을 잠근다.
- 문서 탭은 `보기 / 원본` 두 개로 통합한다. 별도 편집 탭 없이 보기의 셀·블록·필드·상세 영역에서 가능한 범위를 편집한다.
- Markdown 보기는 CodeMirror 6 전체 문서 연속 편집과 라이브 프리뷰를 제공한다. 본문 글꼴은 15px이며 헤더·코드·이미지 표기도 정수 px 크기를 사용한다. 편집기와 미리보기는 같은 크기 변수를 쓴다. 활성 편집 행은 monospace로 표시한다. 긴 줄은 편집 화면 너비에 맞춰 자동 줄바꿈한다. 빈 줄을 포함해 주 커서 또는 IME 조합이 있는 물리 행 하나만 편집 강조와 원문으로 표시한다. 다중 선택에서도 활성 행은 한 줄로 제한한다. 같은 문법 블록의 나머지 행은 구문 트리 기반 Decoration으로 미리보기하며, 헤더와 인용 같은 구조별 행 높이는 편집 중에도 유지한다. 인용 안의 목록은 추가 들여쓰기하고 인용선은 직선으로 표시한다. Markdown 보기의 선·코드·체크 상자·이미지 모서리는 둥글게 처리하지 않는다.
- Markdown 첫 범위는 제목·굵게·기울임·취소선·인라인 코드·링크·목록·인용·체크리스트다. 체크 동작은 `[ ]`/`[x]` 원문만 바꾼다. 중첩 목록은 읽기 보기와 라이브 편집 보기에서 단계별 들여쓰기를 적용한다. 앞쪽 빈 줄은 건너뛰고 첫 부분의 YAML frontmatter를 닫는 구분선까지 감지해 본문 폭 카드로 렌더링한다. YAML의 긴 줄은 카드와 Markdown 편집기 폭을 늘리지 않도록 줄바꿈한다. `YAML 편집`을 시작하면 YAML 내용만 Monaco Editor에서 수정하며 구분선·개행·주변 원문을 보존한다. 표는 일반 Markdown 표로 렌더링하고 `표 편집`을 시작하면 CSV 그리드로 바꾼다. 셀·행·열 변경은 해당 Markdown 표 블록에 반영하며 열 정렬과 편집하지 않은 셀의 Markdown 구문을 보존한다. 코드 블록은 지원 언어의 구문 강조를 적용해 렌더링하고 `코드 편집`을 시작하면 해당 블록만 Monaco Editor로 바꾼다. 편집 내용은 Markdown 원문에 반영하고 코드 펜스와 언어 정보를 보존한다. 이미지와 미지원 구문은 원문으로 편집한다.
- 보기와 원본은 같은 세션 Markdown 문자열·revision·Undo/Redo를 사용한다. BOM·기존 개행·미편집 구문을 유지하고 HTML에서 Markdown을 만들지 않는다.
- 원본은 현재 작업본의 전체 텍스트를 데스크톱 Monaco Editor와 모바일 CodeMirror로 표시·편집한다. 두 탭은 같은 작업본과 변경 이력을 사용하며, 원본 입력 직후 전환·내보내기에도 최신 내용을 보존한다.
- CSV 원본은 감지된 구분자와 인용 필드·이스케이프 따옴표를 구문 강조하고, 각 열 값은 8색 순환 팔레트로 구분한다. 여러 줄 인용 필드에서도 열 색을 유지하며 화면 강조가 원문을 바꾸지 않는다.
- 원본 문법 오류에서는 마지막 유효 보기를 구분하고 오래된 구조를 사용한 편집을 막는다. 입력한 원문은 수정·내보내기·로컬 복구가 가능해야 한다.
- 파일 선택·다중 드롭·붙여넣기, 열린 파일 전환, 명령 검색, 실행 취소·되돌리기, 로컬 작업 복구를 제공한다.
- 명령 메뉴의 파일 열기는 하나로 통일하고, 새 파일 만들기는 형식별로 제공한다.
- CSV 표 검색·필터·정렬·셀 범위 편집·복사/붙여넣기·채우기와 열 너비 자동 맞춤(파일을 열 때 적용), Markdown 서식 및 Markdown 표의 셀·행·열 편집, ICS 반복·시간대, VCF 반복 필드·다중 연락처를 처리한다. EML 보기 화면은 메일 필드·본문·첨부를 수정하지 않는다. 지원하는 이메일 첨부는 새 작업 문서로 열고, 다른 첨부는 내려받는다.
- 원본 탭은 형식 공통 원문 편집기다. EML 보기 화면은 읽기 전용이다.
- PWA 설치·오프라인 편집·업데이트를 지원한다. OS 파일 연결·공유 수신은 지원 환경에서 제공하고 일반 파일 선택을 함께 유지한다.
- 확장 도구모음과 링크 메뉴는 작은 중계 페이지를 연다. HTTP(S) 링크를 가져오기 전 대상 사이트를 확인하고, 파일 자동 열기 규칙과 파일 URL 접근 안내를 유지한다.
- 확장 티켓은 확장 전용 IndexedDB에 최대 10분 보관한다. PWA가 복원·저장한 뒤 티켓을 완료하며, 연결·파싱·저장 실패는 재시도할 수 있다.
- 파일을 여는 동안 진행 문구·다이얼로그·완료 알림을 표시하지 않는다. 실패만 비모달 오류와 재시도로 안내한다.
- 기존 확장에 저장된 작업은 편집 상태와 첨부 관계를 포함해 문서별로 이전한다. PWA 저장 확인 전 기존 저장 데이터를 삭제하지 않는다.

## 4. 공통 UX 원칙

- [기준 목업](../mockup/The%20Viewer.html)의 12개 화면에 있는 디자인 속성·수치·배치·세부 상태를 준수한다. 사용자 요청으로 변경한 두 탭과 보기 안의 편집 동작은 이 문서의 요구사항을 우선한다.
- JSON/YAML/TOML의 기준은 [이번 보관본](../mockup/JSON%20%EB%B7%B0%EC%96%B4%20%EB%94%94%EC%9E%90%EC%9D%B8.html)이다. 블록 자체의 충실도를 기존 공통 스타일 예외로 처리하지 않는다.
- 2026-11-01 후속 [직접 조작 검토](../mockup/review-source/live-review.md)에서 사용자 Chrome의 원본에 날짜·TOML·버튼 Undo·확대·팬·맞춤·왼쪽 폭 조절을 확인했고 드롭의 kind null 참조 오류를 재현했다. 원본 소스·기존 이미지·DOM 대역 점검과 구분한다. 8개 사례군 전체·키보드/IME·모바일·CSS 실측은 미확인이고, 과거 live 수치를 현재 제품 실측값으로 쓰지 않는다.
- 날짜 팝오버는 즉시 반영하며 시간 해제 시 시간대가 비활성화되고, 빈 곳 클릭은 닫기, Undo는 변경 복원이다. 입력의 Escape 닫힘은 원본에서 직접 확인하지 못했으므로 기존 입력 요소의 키 처리로 명확히 연결한다. 새 적용/취소 푸터는 추가하지 않는다.
- 이번 구조 데이터 작업에서는 목업에 없는 기능·요소를 추가하지 않는다. 별도 목업이 없는 다크·모바일 외곽 배치만 기존 공통 규칙에 대응한다.
- 시스템·라이트·다크 테마와 데스크톱·모바일 반응형을 제공한다.
- 모바일 브라우저의 페이지 확대를 막고, 보기의 읽기 영역에서 Ctrl+휠 또는 핀치로 확대·축소한다. 보기 안의 입력과 원본 편집기의 키보드·휠·핀치 동작을 방해하지 않는다.
- 파일 파싱·편집은 기기 내부에서 수행하고, 원본 바이트와 현재 작업본을 분리해 보존한다.
- 파일 본문·첨부를 자동 업로드하지 않으며 HTML·Markdown의 위험한 내용과 외부 자원 요청을 제어한다.
- 편집·내보내기·복구의 실패와 취소를 처리하고, 손상된 작업본도 회수 가능하게 한다.

## 5. 빌드·배포

- PWA는 `./dist/app`, 중계 전용 Chrome 확장은 `./dist/chrome_extension`, ZIP은 버전별 `./dist/the-viewer-chrome-v<version>.zip`으로 빌드한다.
- GitHub Pages workflow는 PWA 전용 검사 후 `./dist/app`의 내용만 올린다. Chrome 확장 빌드와 ZIP 배포는 별도의 수동 작업으로 관리한다.
- 두 타깃의 빌드가 서로의 산출물을 삭제하지 않아야 한다.
- 저장소 하위 경로와 루트 배포에 맞춰 자산·manifest·서비스 워커의 base를 일치시킨다.
- 확장 폴더와 설치 가능한 ZIP을 별도로 제공한다.

## 6. 배포 정보와 남은 확인

- 원격 저장소: [m00nlygreat/the_viewer](https://github.com/m00nlygreat/the_viewer), 기본 브랜치 `main`.
- PWA: [GitHub Pages 배포](https://m00nlygreat.github.io/the_viewer/). Actions가 `dist/app`만 배포한다.
- Chrome 확장 ZIP은 [다운로드 페이지](https://m00nlygreat.github.io/the_viewer/downloads/the-viewer-chrome-latest.zip)에서 제공한다. Chrome Web Store 게시 범위는 아니다.
- PWA 공개 후 서비스 워커 캐시 준비 뒤에는 로컬 파일 전달을 오프라인에서 사용할 수 있다. Chrome 확장 연결·파일 전달과 ZIP 배포는 확장 검증 후 별도로 관리한다.
